# Передача Ярославу и его GPT

## Контекст задания

Практическая работа № 2 посвящена модульному и мутационному тестированию. Команда из четырёх человек работает парами:

- Саади и Ярослав разрабатывают общий модуль обработки строк; каждый пишет по пять функций.
- Артём и Влад разрабатывают модуль обработки файлов.
- Затем пары обмениваются модулями и проверяют их тестами.
- По условию у каждого участника одна из пяти функций должна содержать намеренный логический дефект.

Выбран Python. Планируемый тестовый фреймворк — pytest.

## Что уже готово

Файл saadi_strings.py содержит пять функций Саади и их docstrings. Контракты перечислены в README.md. Не переписывай и не переименовывай эти функции без согласования: Артём и Влад будут составлять тесты по этим контрактам.

Из пяти функций Саади одна намеренно дефектная. Точный пример находится в AUTHOR_NOTE_KNOWN_DEFECT.md. Это заметка для разработчиков и передачи контекста; не прикладывайте её к материалам тестирования, если хотите, чтобы тестировщики сначала проверили модуль по спецификации.

## Следующие шаги Ярослава

1. Согласовать, чтобы функции не дублировались.
2. Добавить пять своих функций в отдельный файл yaroslav_strings.py, не редактируя saadi_strings.py.
3. Описать для каждой функции сигнатуру и правила поведения, включая пустой ввод и границы.
4. В одной своей функции оставить один логический дефект, как требует задание.
5. Передать оба файла и спецификации Артёму и Владу для тестирования общего строкового модуля.
6. После отчёта о дефектах внести исправления и повторно прогнать тесты. Затем выполнить мутационное тестирование.

Предлагаемые функции Ярослава, если список ещё не согласован: is_palindrome, count_digits, remove_punctuation, replace_substring, count_uppercase. Перед реализацией согласуйте их контракты и убедитесь, что они не дублируют функции Саади.
